01 / A LITTLE ABOUT ME

I like the work behind the work.

I’m interested in what happens after the code is written: how a job behaves at scale, whether a deployment can be repeated, and where a person still has to step in to do something a system should handle.

Working in fintech has made those questions practical. There’s usually someone waiting on the other end of a report, a file, or a decision. The little details matter because they add up for that person.

Lately I’ve been thinking about how to design distributed systems that stay understandable as they grow, and where AI genuinely removes busywork rather than adding to it.

03 / THINGS I’VE BUILT

Much of my day-to-day work isn’t public. Here are the problems behind a few things I’ve worked on.

01 / AI & AUTOMATION

When document reviews take too long

Comparing technical documents by hand is slow and easy to get wrong. I built an AI-assisted comparison and validation tool using OpenAI APIs, React, and backend services to help surface differences automatically.

97% comparison accuracy · less time spent on manual validation

02 / BACKEND

Invoices, minus the wait

I developed a Java and Spring Boot reporting platform for invoice generation, then worked on the application and workflows to reduce processing time.

30% less time to generate invoices

03 / CLOUD

Getting work out of the queue

AS400 queue-based processing was holding up workflows. I designed AWS Step Functions flows for parallel processing so the system could scale without depending on that queue.

AWS Step Functions · distributed processing

04 / DELIVERY

A smoother road to production

I automated AWS infrastructure with Terraform and Chef, maintained Jenkins pipelines, and implemented CDN-based delivery so files could reach clients more quickly.

40% lower download latency
